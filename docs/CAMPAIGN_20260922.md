English is the default documentation language. Package guides link to the preserved Korean versions. These added English guides do not alter the original package files or their hashes.

## Current repaired protocol

The four trainer files in `swan_repaired_v1` already matched the supplied source files byte for byte at import. They were not edited. The current repaired A/B/C comparison uses 76,950 successful optimizer updates with validation every 2,565 updates, saved preprocessing from training data, and EMA checkpoints selected by validation Hs MAE. Do not apply the older root-level workflow's final-raw-weight or Kendall-validation-loss selection policy to these results.

Candidate selection for FNO, FFNO, and TNO uses the repaired pilot/A/B validation results. C adds seeds 43 and 44 to the selected seed-42 configuration. D/E are omitted in the v3/v4 route. The seven additional architectures use fixed configurations and three seeds; they did not receive the same architecture search. Comparisons must acknowledge that difference.

The v4.1 controller reads/writes the existing `runs/iclr_parallel_v4` root. A missing `completed.json` alone does not indicate failure: all required families must finish evaluation before it is written. `partial_completed.json` is not a live progress marker.

## Event diagnosis

The current standalone diagnosis is scoped to 2021 Hs. It reuses validated peak snapshots and re-infers missing event hours from the frozen checkpoint. It preserves the original evaluation outputs and compares each frame's MAE with the original hourly CSV. Default models are FNO, FFNO, and TNO; default seeds are 42, 43, 44; the original frozen event windows are retained.

```bash
python3 swan_event_diagnostics_v1/run.py inspect
bash swan_event_diagnostics_v1/START.sh --gpus 2,3
```

The command requires GPUs 2/3 to be free and not allocated by another controller. It does not coordinate GPU reservations with other launchers. See the package README for outputs, resumption, and report collection.

The historical audit script converts saved input-start indices to target indices using sequence length. It reports target split membership and temporal overlap with training inputs. It does not implement 2019-2020 event re-inference. Historical events must not be presented as independent unseen cyclones when their windows include training data.

## Scientific limits and outstanding work

- Source Tm values above 30 s, including an extreme value near 4,962 s, were reported in the held-out summaries. Verify source data, masking, and transformations before drawing final Tm conclusions or extending training with that year. No automatic clipping or repair is included.
- Aggregate MAE, conditional high-wave errors, and errors at the actual peak location/time answer different questions. Keep these definitions separate.
- Event diagnostics proposed after looking at 2021 results are exploratory. Additional tuning requires an appropriate independent confirmation set, such as untouched 2022 data.
- v5 changes training years and preprocessing/split details. It is not a pure isolated test of data quantity.
- Robustness perturbations, memory-accuracy profiling, and additional baseline learning-rate searches were discussed but are not implemented in this import.
- No new inference speed, geographical generalization, or statistical superiority claim follows from importing code.

## Validation and provenance

Package SHA256 manifests match all imported package files. Python sources parse successfully. Existing package unit tests were run separately to avoid collisions between identically named modules in different version folders: 70 tests, 69 passed, one optional synthetic NetCDF test skipped. The tests include synthetic scheduler/process fixtures; they did not operate on the user's training server.

Actual B200 inference and full training were not rerun during this import. Preserve the delivered package hashes and original run manifests. Do not replace an earlier run's unknown or different Git commit with this snapshot's commit. The repository's existing pre-run tag requirement applies before a subsequent new experiment is launched.
